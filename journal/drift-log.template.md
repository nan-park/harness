# 이탈 기록 (drift log)

> **이탈 기록 장부.** 프로젝트 kickoff에서 사용자가 이 기록에 동의한 경우에만 쓴다.
> 기본 위치는 `~/.claude/harness/journal/drift-log.md`이며 `HARNESS_DATA_DIR`로 바꿀 수 있다.
> `./install.sh`가 장부가 **없을 때만** 이 서식으로 만든다. 재설치와 제거는 기존 기록을 보존한다.
>
> 공개해도 되는 요약(어떤 실패로 어떤 규칙이 생겼나)은 `journal/changelog.md` 에 옮겨 적는다.

하네스 개선의 **유일한 근거**다. 여기 쌓인 것만 보고 헌법·스킬·훅을 고친다.
감으로 개선하지 않는다.

## 언제 적는가

- 사용자가 방향을 되돌렸을 때 ("그거 말고", "다시 해줘", "왜 그걸 건드렸어")
- 재작업이 발생했을 때
- 승인 없이 등급 A에 해당하는 일을 해버렸을 때 (스스로 알아챈 경우도 포함)
- 물어봤어야 했는데 추측으로 진행한 것을 나중에 발견했을 때

**기록은 등급 C다.** 사용자 승인 없이 그때그때 바로 적는다. 세션이 끝나면 잊혀지기 때문이다.

## 유형 분류

| 유형 | 정의 | 개선이 향하는 곳 |
| --- | --- | --- |
| **방향** | 요구와 근본적으로 어긋남, 범위 축소·누락 | 헌법 §2 등급표, kickoff 인터뷰 질문 |
| **실행** | 방향은 맞으나 버그·미완성·연결 끊김 | 적대 리뷰, 검증 절차 |
| **품질** | 동작하지만 기대에 못 미침 | 채점 기준, 프로젝트 CLAUDE.md의 성공 기준 |

## 개선 트리거

**정본은 헌법 §10이다.** 아래는 기록하는 자리에서 바로 보라고 옮겨둔 사본이다.
헌법을 고치면 여기도 맞춘다.

기록할 때 같은 유형이 몇 번째인지 세고, 아래에 도달했으면 **그 자리에서 사용자에게 알린다.**
알리는 것까지가 여기 범위다 — **하네스 수정 자체는 등급 A라 승인 없이 하지 않는다.**

| 조건 | 하는 일 |
| --- | --- |
| 같은 유형 3회 누적 | 해당 유형의 개선처(위 표)를 손본다 |
| 전체 5건 누적 | 다음 버전 설계를 검토한다 |
| 훅으로 막을 수 있는 것이 2회 반복 | 훅을 만든다 (지시문으로 안 되는 것이 증명된 셈) |
